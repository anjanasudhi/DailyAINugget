# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-script bot (`daily_ai_nugget.py`) that runs once a day (via GitHub Actions, scheduled 9:30 AM IST — see `.github/workflows/daily-nugget.yml`) and delivers a 15-20 minute "daily FDE learning coach" session: a day-of-week-driven deep dive (AI/ML, software engineering, news roundup, FDE case study, martech, engineering leadership, or a Sunday recap/quiz) plus quick news, a case snippet, an interview question of the day, and a spaced-repetition recall check. Generated by Claude with web search, then sent out over both email (Resend API) and Telegram (Telegram Bot API).

The content structure follows `daily-fde-learning-coach-prompt.md`, a conversational-coach spec originally written for a persistent-chat app (Claude Project/GPT). This script adapts it for one-way scheduled delivery — see the "NOTE ON INTERACTIVITY" section in the script's docstring for what had to change (no reply-parsing, so the model answer to each day's interview question is always revealed at the start of the *next* day's message rather than waiting to see if it was attempted).

## Commands

```
pip install -r requirements.txt              # install deps (anthropic, python-dotenv)
python daily_ai_nugget.py --dry-run           # generate + print the message, don't send (state still advances)
python daily_ai_nugget.py                     # generate, send email + Telegram, advance rotation state
python daily_ai_nugget.py --pillar ai_ml      # override today's deep-dive pillar for this run (testing)
python daily_ai_nugget.py --reset-state       # wipe coach_state.json (cursors, pending question, history)
```

There is no build step, test suite, or linter configured in this repo.

## Configuration

All secrets/config are read from a `.env` file (via `python-dotenv`) locally, or from GitHub Actions repo secrets in CI — see `.env.example` for the required keys (`ANTHROPIC_API_KEY`, `RESEND_API_KEY`, `EMAIL_TO`, `EMAIL_FROM`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). `.env.example` must only ever contain placeholder values — real credentials belong in `.env` (local) or repo secrets (CI) only.

## Architecture

Everything lives in `daily_ai_nugget.py`, structured as a pipeline called from `main()`:

1. **Planning** (`build_plan`) — `PILLAR_BY_WEEKDAY` maps day-of-week (IST) to a deep-dive pillar. Pillars with a `TOPIC_BANKS` entry (ai_ml, swe, fde_case, martech, leadership) get a rotating subtopic via `_next_from_list`, which persists a per-pillar cursor in `coach_state.json` so subtopics cycle without repeating. `news_roundup` and `review_quiz` pillars have no bank — they're driven by live search / recent history instead. A separate `fde_snippet` cursor rotates the FDE case-study bank independently for the short daily case snippet (skipped on Thursdays, when the deep dive already covers it). `INTERVIEW_CATEGORIES` rotates the same way for the daily interview question.
2. **Content generation** (`generate_nugget` / `_build_prompt`) — calls the Anthropic Messages API with the `web_search_20250305` tool. The prompt is assembled per-pillar (different instructions for a normal concept explainer vs. the Wednesday news roundup vs. the Thursday deep FDE case vs. the Sunday recap/quiz), and asks Claude to append a machine-readable `<<<STATE>>>...<<<END_STATE>>>` block with the day's verbatim interview question and a one-line concept summary. `_split_state_block` parses that block out and strips it before the message is sent; `main()` uses it to update `coach_state.json`'s `pending_interview` (revealed at the top of tomorrow's message) and `history` (last 8 entries, used for the recall check and Sunday recap).
3. **Delivery** — `send_email` (Resend API) and `send_telegram` (Telegram Bot API) are both called unconditionally in `main()` unless `--dry-run` is passed. `send_telegram` chunks the message via `_chunk_message` to stay under Telegram's 4096-character API limit (the coach message routinely exceeds it). Both delivery functions use `urllib` directly (no HTTP client dependency) and require a `User-Agent` header to avoid Cloudflare/API bot-blocking.

`sys.stdout.reconfigure(encoding="utf-8")` is set at import time because the generated messages contain emoji and the script is run non-interactively, where the default console codepage isn't always UTF-8.

### GitHub Actions

`.github/workflows/daily-nugget.yml` checks out the repo, installs deps, runs the script with secrets injected as env vars, then — only if that step succeeded — commits and pushes the updated `coach_state.json` back to the repo so rotation cursors/history/pending question persist across runs (GitHub-hosted runners are ephemeral). If the send step fails partway (e.g. one delivery channel errors), the persist step is skipped, so the next run naturally retries with the same plan rather than silently skipping content.
